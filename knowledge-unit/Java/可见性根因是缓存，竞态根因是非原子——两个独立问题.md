## 1. 它解决了什么问题？
volatile 和 synchronized 解决的是同一个问题吗？为什么需要两种不同的机制？
## 2. 它的核心矛盾是什么？
并发问题的两种表现（看到旧值 vs 操作被打断）看起来像同一个问题，但根因完全不同，需要不同的解决方案。
## 3. 它的本质模型是什么？
- **可见性** → 根因是 **CPU 缓存**：硬件为性能引入缓存层，导致一个 CPU 的写入对另一个 CPU 不可见
- **竞态条件** → 根因是 **操作不原子**：read-modify-write 是多步操作，即使没有缓存，多 CPU 同时执行也会交错覆盖
两者独立存在，独立根因：volatile 只解决可见性，synchronized 两个都解决（互斥 + 可见性）。
## 4. 它还能解释什么？
- 区分"看到的数据不对"和"操作被打断"是分析所有并发问题的起点
- Atomic 类解决竞态但不依赖锁（CAS 是原子操作）
- 分布式系统中的 "读到旧数据"（副本延迟）vs "写冲突"（非原子操作）也是同样的拆分
## 5. 认知变化
**以前我以为：** 可见性和竞态是同一个问题的两面
**现在我认为：** 两者根因独立——缓存 vs 非原子，需要分开分析和解决
## 6. 最终压缩
> 可见性根因是 CPU 缓存（读到旧值），竞态根因是操作不原子（read-modify-write 多步可交错），两者独立，volatile 只解决前者，synchronized 两个都解决。
