## 1. 它解决了什么问题？
什么时候多线程真正有帮助？多线程的收益条件是什么？
## 2. 它的核心矛盾是什么？
多线程收益来自填满CPU空闲时间，但线程切换本身也在消耗CPU时间。线程越多，协调成本越高，收益存在天花板。
## 3. 它的本质模型是什么？
多线程的收益不是来自"并行"本身，而是来自填满CPU的空闲等待时间。分为两层：
- IO密集型场景：单核多线程即受益，因为CPU在IO等待时空闲，切换出去干活是赚的
- CPU密集型场景：需要多核才能受益，每个核跑一个线程实现真正并行
但多核并行又引出新问题：缓存一致性（MESI协议），两个核操作同一块内存时需要同步，这在单核世界不存在。
## 4. 它还能解释什么？
- 数据库连接池：连接等待时可以处理其他请求，本质也是填空隙
- 异步IO / 事件循环：用单线程+非阻塞IO达到类似效果，但避开了多线程的协调成本
- 协程/虚拟线程：用更轻量的调度减少切换成本，让"填空隙"更便宜
## 5. 认知变化
**以前我以为：** 多线程的好处就是并行，越多线程越快
**现在我认为：** 多线程的收益来自填满等待空隙；线程数超过核心数后，切换成本会吃掉收益；多核解决了并行但打开了共享状态协调的潘多拉盒子
## 6. 最终压缩
> 多线程收益的本质是填满CPU空闲，不是并行本身。IO密集单核即受益，CPU密集需多核。协调成本随线程数增长是隐性税。
