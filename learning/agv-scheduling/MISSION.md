# Mission: AGV / 机器人调度系统(从零到工业级)

## Why
学习者是一名后端工程师(Java/Kotlin/Python),有 AGV/AMR 的接触经验,**目前的工作就是在做人形机器人**。所以「工业级调度系统」的最终落地场景明确偏向**人形/具身**,而人形调度恰好是整个领域最前沿、最难的部分。希望**完整、系统地从浅入深建立知识体系**,最终目标是可以**独立实现一个工业级的调度系统**(以人形/具身为重点场景),同时补充硬件相关知识。机器人领域已有实际接触(不是零基础),但**算法/数学基础偏弱是当前最需要补的短板**;需要一个把后端经验迁移过来、从最底层概念讲起、并能通向人形调度的完整路径。

后端工程师的身份是核心优势:调度系统的"大脑"本质上就是一个分布式后端系统——任务编排、状态机、路径计算、冲突仲裁、实时通信。本课程将反复利用这个类比来加速学习。

## Success looks like
- 能讲清楚一个工业级 AGV/机器人调度系统由哪些子系统构成,各子系统职责与边界(L0~L1 认知)
- 能独立实现**单机**层面的:地图建模 + 单车路径规划(A*/RRT)+ 运动控制基础(L2)
- 能独立实现**多机**层面的:任务分配 + 冲突检测与消解(MAPF/CBS)+ 死锁防护(L3)
- 能讲清楚**多机器人系统(MRS)**与**人形/具身机器人调度**的差异,知道如何把 AGV 调度能力**迁移到人形场景**(L4,L4-02 人形调度是核心必达目标)
- 能描述 AGV 硬件架构(底盘/驱动/导航/通信/传感器),能跟硬件团队对话、做系统选型(硬件模块)
- 能产出一份**工业级调度系统的架构设计文档**(以人形/具身为重点场景),并在白板上讲清每个决策的权衡(L5 综合实战)

## Constraints
- 算法/数学基础薄弱(这是当前最需要补的短板),需要从最基本概念讲起(不假设会图论/最优化/控制论)
- **已有 AGV/AMR 实际接触经验,在做具身人形** → 机器人领域不是零基础,L0-02 的车型/导航等内容可加速,但需确认细节理解是否扎实
- 硬件只到"架构层面",不深入电路/驱动级(但要知道接口、参数、选型逻辑)
- 后端编程能力强(Java/Kotlin/Python),可大量复用类比(状态机≈订单系统、路径规划≈路由、MAPF≈分布式锁)。**L1/L2/L5 的代码示例默认用 Python**(算法可读性最好,贴近机器人生态),涉及并发/系统架构时用 Java/Kotlin 类比
- 系统会持续演进,知识体系要扎实、可迁移,优先建立"地基"而非速成
- **人形调度是工作刚需** → L4-02 提升为必达核心,并在 L1~L3 各处埋下通向人形的伏笔

## Out of scope(暂不深入)
- 底层电路设计、电机驱动级 PID 调参到电路细节
- 深度学习/强化学习训练到模型架构层(只在需要时点到为止)
- 具体 ROS 版本的 API 细节(讲原理与架构,API 查文档)
- 单一厂商私有协议的逆向

## 整体路线图(6 大阶段 / L0→L5)

详见 `reference/ROADMAP.md`。一句话概览:

- **L0 地基**:为什么需要调度、一个调度系统的全景、AGV/机器人是什么、后端经验如何迁移
- **L1 单机能力**:地图建模、单车路径规划(A* / Dijkstra / RRT)、运动学与轨迹
- **L2 多机调度核心**:任务分配、冲突检测与消解(MAPF / CBS / 免疫算法)、死锁防护
- **L3 工程化**:实时性、状态同步、故障容错、调度引擎架构、通信协议(VDA5050)
- **L4 拓展**:多机器人系统(MRS)、人形/具身机器人调度差异、群体智能/强化学习入门
- **L5 综合实战**:从零设计并实现一个工业级调度系统(模块化、可演示)
- **硬件模块**(横向穿插):AGV 硬件架构、导航方式、通信、传感器、选型
