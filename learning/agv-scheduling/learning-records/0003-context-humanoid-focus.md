# 关键背景更新:在做具身人形,聚焦人形调度

L0-02 会话中,学习者披露了三条影响教学重心的重要信息:

1. **目前的工作就是在做人形机器人**(不是通用 AGV 方向)
2. 已有 **AGV/AMR 的实际接触经验**(机器人领域非零基础)
3. 熟练语言:**Java / Kotlin / Python**

## 为什么这条记录极其重要
它把整个课程的**落地场景从"通用 AGV 调度"聚焦到"人形/具身调度"**。人形调度是这个领域最前沿、最难的部分(高自由度、技能多样、人机混行),L0-02 原本把 L4-02 列为"选读",现在必须**提升为必达核心**。

## 对教学路径的具体调整
1. **MISSION.md / NOTES.md 已更新**:落地场景改为人形/具身重点;L4-02 提升为必达核心
2. **机器人领域内容可加速**:L0-02 这类车型/导航知识,学习者已有经验,点过即可,但要抽查细节是否扎实(比如刚确认了 AGV/AMR/底盘运动学/集中式都答对)
3. **算法/数学仍是短板,不加速**:这是最需要补的,继续从零讲
4. **代码示例默认 Python**(算法可读性 + 机器人生态主流);并发/架构话题用 Java/Kotlin 类比
5. **L1~L3 每处埋通向人形的伏笔**:
   - L1-05 运动学 → 伏笔:人形是几十个关节的高自由度,运动学复杂度爆炸
   - L2-01 任务分配 → 伏笔:人形任务不只是"去某点",是"执行某个技能"
   - L3-01 调度引擎架构 → 伏笔:人形调度更像"技能编排引擎"(Temporal/Airflow 式)
   - L3-04 故障容错 → 伏笔:人形跌倒/卡住的恢复比 AGV 复杂得多

## 关于"已掌握"的诚实记录
L0-02 自测 4/4 全对(AGV/AMR/底盘运动学/集中式架构)。术语表中这些概念已可 promote。学习者机器人领域的底子比预想扎实,可以放心加速 L0 剩余内容,把时间集中投到算法短板和人形专题上。
