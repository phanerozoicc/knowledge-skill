L0-02 · AGV / 移动机器人是什么

阶段 L0 地基 难度:入门 前置:L0-01 预计:40 分钟
🎯 这节课你将学会:看到一个应用场景,能准确判断「这该用 AGV 还是 AMR、什么导航方式、什么底盘」,并讲清它们和你最终要做的调度系统的关系——也就是:被调度的「对象」到底是什么,它有哪些属性会影响调度决策。

先破一个最容易混的概念:AGV vs AMR

这两个词在行业里被混用得很厉害,但它们对调度系统的影响完全不同,必须分清。一句话区分:

AGV(Automated Guided Vehicle,自动导引车):走固定/预设路线,像火车,笨但可靠。调度它 = 排运行图。
AMR(Autonomous Mobile Robot,自主移动机器人):能自己看路、自己绕障,像出租车,灵活但难管。调度它 = 下指令、放权。

AGV(导引车)AMR(自主机器人)
怎么认路磁条/二维码/反光标记,跟着预设路径SLAM 自建地图,实时规划
遇到障碍停下等人来(或停死)自己绕过去
路线灵活性低,改路线要改物理设施高,地图一改全队更新
对调度的依赖极高——车自己不会避让,全靠中央调度中等——车能自治,调度更多是协调
典型场景大流量、重复路线(产线送料、港口)多变环境(仓储拣货、医院配送)
成本/可靠性单车便宜、极其稳定单车贵、灵活但故障面更大
  • AGV ≈ 静态路由 / 固定专线:像你给某个服务配死的路由规则,流量打过来无脑转发,简单可靠,但换个路径要改配置。
  • AMR ≈ 动态路由 / 服务发现:像带服务发现的智能路由,每个节点自己探测环境、自己选路,灵活但需要更复杂的协调协议。
对你做调度系统的影响:AGV 场景里,调度系统是「上帝」,几乎所有智能都在中央,车只是执行器;AMR 场景里,智能部分下放到车端,调度系统更像「协调者」。这就是 L3-03 为什么要学 VDA5050——它就是为了在「中央智能」和「车端智能」之间划清边界而生的标准。
⚠️ 行业现实:别太纠结字面 实际产品里界限很模糊。很多「AGV」其实带 SLAM,很多「AMR」也能走固定路线。供应商的营销话术更是乱来。你要建立的不是死记定义,而是看一台车时,问三个问题(见下面 2.3),这三个问题的答案才真正决定它对调度的影响。

AGV 的几种主要形态

除了 AGV/AMR 这个「智能程度」的轴,还有「干什么活、长什么样」这条轴。常见有这几类,调度系统对它们的处理方式差别很大:

类型干什么调度特点
搬运 AGV / Kiva 式钻到货架底下,把整个货架驮走任务简单(点对点),但数量极大(亚马逊数万台),核心是规模化调度
叉车 AGV自动叉车,叉托盘搬运载重大、运动学约束强(阿克曼,不能原地转),调度要考虑转弯半径
牵引 AGV拖一串小车(像火车头)拖挂队列,长度长、倒车难,路径规划要预留更大空间
料箱机器人在货架上爬上爬下取料箱既有移动也有机械臂动作,调度要管两段
合流/分拣 AGV带着包裹到分拣口大量车汇入汇出,核心是路口交通管制
人形 / 具身机器人类人形态,执行多样任务见 L4-02,调度难度高一个量级

看一台车时,问这三个问题

这是本课最实用的产出。以后无论是选型、看方案、还是设计调度,对着任何一台移动机器人,问这三个问题,就能摸清它对调度系统的影响:

问题 1:它怎么认路?(导航方式)

决定了「地图数据从哪来、改路线的成本、定位精度」。主要几类(HW-02 会深入):

  • 磁条/色带:物理贴线,最老最稳,改路线要重新贴。
  • 二维码/反光标记:地上贴码,经过时定位,精度高,Kiva 就用这种。
  • SLAM(激光/视觉):自己建图自己定位,最灵活,环境变化大时首选。
  • GPS/RTK:室外港口、园区,精度米级到厘米级。

问题 2:它怎么动?(底盘运动学)

决定了「能不能原地转、转弯半径多大、路径能不能随便画」。主要几类(L1-05、HW-03 会深入):

  • 差速驱动:两个轮子转速差转向,能原地转,最灵活但只能平面。
  • 阿克曼:像汽车,前轮转向,有转弯半径,不能原地转(叉车 AGV 常见)。
  • 全向(麦克纳姆/舵轮):能横着走、斜着走,极致灵活,轮子贵。
为什么这个对调度要紧 你做路径规划时,「能不能原地转」直接决定路径能不能有直角。差速车能原地转 → 路径可以是格子直角;阿克曼不行 → 必须用平滑曲线(Dubins/Reeds-Shepp,L1-05 会讲)。底盘构型 = 路径规划的硬约束。

问题 3:它有多少自治权?(智能在中央还是车端)

决定了「调度系统的边界在哪」。这是架构问题:

  • 中央集权式:所有路径、避让都由调度算好,车只执行(典型 AGV)。调度复杂、车简单。
  • 车端自治式:调度只下发任务「去 X 点」,车自己规划、自己避障(典型 AMR)。调度简单、车复杂。
  • 混合式:常态车端自治,拥堵/特殊区域中央接管。工业实践主流。
这第三问的答案,直接对应你熟悉的架构决策:
  • 中央集权 ≈ 单体服务,所有逻辑在中心
  • 车端自治 ≈ 微服务,每个节点有自己大脑
  • 混合式 ≈ 边缘计算 + 云端协调(也是现在的工业主流)
你会发现,从 AGV 调度的架构演进,到后端架构的演进,几乎是同一条历史轨迹:从全集中,到部分下放,到云边协同。学这门课,你其实是在用新的实例,重新理解你已经知道的架构哲学。

把场景和车型对上号

你列过感兴趣的场景,现在用刚学的三个问题,给每个场景配一个「典型答案」。这就是你未来做方案设计的基本功:

场景典型车型导航底盘智能在哪调度难点
仓储拣货(Kiva)搬运 AGV二维码差速中央极大规模(数千台)的路径与冲突
工厂产线送料搬运/叉车 AGV磁条/SLAM差速/阿克曼中央为主节拍配合、死锁防护
港口集装箱大型 AGV/集卡RTK-GPS+SLAM阿克曼混合大范围、单车贵、户外定位
医院/办公配送AMR视觉 SLAM差速/全向车端自治人机混行、动态障碍
人形/具身人形机器人视觉 SLAM腿足(高自由度)车端为主+技能编排见 L4-02,难度高一个量级
📌 一张表浓缩本课 看到任何移动机器人,默念这三个问题:① 怎么认路? ② 怎么动? ③ 多少自治权?——这三个答案,就决定了它对调度系统的影响。

这和你要做的调度系统什么关系

记住一个定位关系,它贯穿全课程:

调度系统是「大脑」,AGV/机器人是「手脚」。 本课程 90% 的篇幅在打造「大脑」(L1~L5),HW 硬件模块负责让你看懂「手脚」长什么样、能做什么、不能做什么。你要做工业级调度系统,必须既懂大脑,也懂手脚的约束——否则你会设计出「大脑想得美,手脚做不到」的方案。

具体说,AGV 的这些属性会反过来约束调度系统:

  • 底盘运动学 → 约束路径规划能产生什么形状的路径(L1-05)
  • 导航精度与定位频率 → 约束状态同步的实时性设计(L3-02)
  • 自治程度 → 约束调度架构是集中还是分布(L3-01、L4-01)
  • 通信能力 → 约束指令下发与重规划的频率(L3-03)
  • 电池与充电 → 约束任务分配必须考虑电量(L2-01)
这就是典型的「能力发现 + 健康检查」模式:调度系统(中央)必须知道每个 worker(车)的能力清单(能走什么路、转多大的弯)和状态(电量、位置、是否在线),才能正确派活。和你在后端做的服务注册 + 心跳 + 健康检查是同一件事,只是「worker」换成了会动的物理实体。

小结

  • AGV 走固定路线、靠中央; AMR 自己看路、有自治权。两者对调度的依赖程度相反。
  • 区分不要死记字面,用三个问题:① 怎么认路(导航)② 怎么动(底盘)③ 多少自治权(智能分布)。
  • 底盘运动学 = 路径规划的硬约束(差速能原地转、阿克曼不能)。
  • 智能在中央还是在车端,决定了调度架构是集中式还是分布式——这和后端架构演进同构。
  • AGV 的属性(底盘/导航/自治/通信/电量)会反过来约束调度系统的设计。
✅ 自测(每题答案都是 4 个字,完全等长)
  1. 走固定预设路线、自己不会避障、完全依赖中央调度的那类车,英文缩写是?
  2. 能自己用 SLAM 看路、自己绕障的那类车,英文缩写是?
  3. 看一台车时,判断它「能不能原地转、转弯半径多大」对应的是哪方面?
  4. 「所有智能都在中央,车只执行指令」的调度架构,叫什么式?

老规矩,答案发我。这 4 题如果全对,L0-02 就扎实了,我们直接进 L0-03 调度系统全景图——那是最关键的「地图课」,会把整个课程的模块一次性串起来。
