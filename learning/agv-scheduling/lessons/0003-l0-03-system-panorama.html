L0-03 · 调度系统全景图

阶段 L0 地基 难度:入门(信息量大) 前置:L0-01, L0-02 预计:50 分钟
🎯 这节课你将学会:看着一张图,讲清楚一个工业级调度系统由哪些模块组成、各模块职责、数据怎么流转。这是整门课的「地图」——之后你每学一个算法,都能回到这张图问「它在哪一层、哪个模块、优化什么」。本课不深入任何模块的细节,只把骨架立起来。
📌 怎么用这节课 这课信息量大,不要试图一次记住所有细节。目标是建立一张 mental map:看到「A*」「CBS」「VDA5050」这些词,你能立刻定位到图上的某个模块。细节以后每个模块都有专门的课。现在请把这张图当作「目录」反复回看。

这张图你用后端视角看,就是一张实时分布式后端的架构图:
  • 战略层 ≈ 业务编排层(接入外部订单,决定走哪条业务流)
  • 战术层 ≈ 调度器 + 路由 + 锁服务(核心计算都在这)
  • 执行层 ≈ Worker 节点 + 消息总线 + 监控/熔断

12 个模块逐个点名(只认人,不深入)

下面把图里 12 个编号模块逐个过一遍。每个模块:它是干嘛的、对应哪节课、对应你哪个后端经验。现在不必记住细节,只需建立"看到词→定位到模块"的反射。

战略层(任务管理)

① 任务接入 (Task Ingestion)

从外部系统(WMS 仓储管理 / MES 制造执行 / 订单系统)接收原始任务。要处理协议适配、限流、去重、ack。

对应课:L3-03(协议)。后端映射:API 网关 / 消息消费者。人形伏笔:人形的"任务"来源更多元(语音指令、视觉触发、日程系统)。

② 任务编排 (Task Orchestration)

把一个粗粒度任务(如"完成订单 #123")拆成车辆能执行的原子任务(去A点→取货→去B点→放下)。也可反向合并多个小任务提升效率。

对应课:L3-01。后端映射:工作流引擎(Temporal/Airflow/状态机)。人形伏笔 ⭐:人形任务编排复杂度爆炸——"泡杯咖啡"要拆成 移动→开门→取杯→操作咖啡机→移动→递送,每步是一个技能(Skill)。这是 AGV→人形最关键的升级点。

③ 优先级与批量策略 (Priority & Batching)

决定哪些任务先做、哪些合并做、哪些插队。受业务规则(SLA、紧急程度)和效率(顺路合并)双重驱动。

对应课:L3-01。后端映射:优先级队列 + 批处理。

战术层(调度引擎)⭐ 本课程主战场

④ 任务分配 (Task Allocation)

从待执行任务池里,给每台车分配任务。核心权衡:全局最优(算得慢)vs 快速就近(次优但快)。

对应课:L2-01。后端映射:负载均衡器选 worker。人形伏笔:人形任务分配要看"谁会这个技能"——不只是位置,还有能力匹配。

⑤ 路径规划 (Path Planning)

给单台车算一条从当前位置到目标的路线。核心算法:Dijkstra、A*。要考虑底盘运动学约束(能不能原地转)。

对应课:L1-03、L1-04(单车);L2-04(多车协同)。后端映射:网络路由(OSPF 用 Dijkstra)。人形伏笔:人形是高自由度,路径规划升级为"全身运动规划"(L1-06 RRT 的用武之地)。

⑥ 冲突消解 (Conflict Resolution)

确保多台车规划出的路径在时间和空间上不撞。核心问题 MAPF,核心算法 CBS。这是整个调度系统技术含量最高的模块。

对应课:L2-02、L2-03、L2-04(硬骨头,三节课)。后端映射:分布式锁 + 乐观并发控制。人形伏笔:人形之间不只是"位置冲突",还有"手臂工作空间冲突"。

⑦ 交通管制 / 死锁防护 (Traffic & Deadlock)

管路口(谁先过)、单向通道、环形通道(防止 4 车死锁)。冲突消解管"两两不撞",这里管"全局流得动"。

对应课:L2-05。后端映射:数据库死锁检测 + 限流/信号量。

⑧ 地图/拓扑管理 (Map & Topology)

把物理空间抽象成"节点+边+权重"的图,供路径规划使用。维护静态结构(通道)和动态状态(某段路临时封锁)。

对应课:L1-01(本课程第一个动手模块)。后端映射:数据模型设计 / 图数据库。人形伏笔:人形地图不只是 2D 平面,还有 3D 可达性(能伸手够到哪)、语义地图(这是桌子、那是抽屉)。

⑨ 车队状态 (Fleet State)

实时维护每台车的:位置、朝向、速度、电量、当前任务、健康状态。所有决策的输入。

对应课:L3-02。后端映射:服务注册中心 + 心跳/健康检查。

执行层(车辆管理 + 通信)

⑩ 指令下发 (Command Dispatch)

把规划好的路径/动作翻译成车辆能理解的指令序列,通过协议下发给车。

对应课:L3-03(VDA5050)。后端映射:RPC 调用 / 消息推送。

⑪ 状态上报 (State Reporting)

车辆持续上报位置和状态。频率和可靠性直接决定调度质量(数据陈旧=瞎调度)。

对应课:L3-02。后端映射:遥测 / metrics 上报。

⑫ 故障 / 容错 (Fault Tolerance)

车掉线、死车、电量耗尽、地图封锁——检测、处理、重分配、降级。生产系统 7×24 稳定的关键。

对应课:L3-04。后端映射:熔断、重试、补偿事务、最终一致性。人形伏笔:人形跌倒/卡住的恢复远比 AGV 复杂(AGV 停了等人推,人形要自主站起来)。

一次完整的数据流(把模块串起来)

用 L0-01 那个「1 个订单的旅程」的例子,但这次标注它经过了哪些模块。把编号对回上面的图:

WMS 下发"搬 3 号货架到 P12"
  │
  ▼ ①任务接入 → ②任务编排(拆成:去3号→驮起→去P12→放下) → ③优先级(普通)
  │
  ▼ ④任务分配:查 ⑨车队状态,选最近、有电、空闲的 AGV-04
  │
  ▼ ⑤路径规划:查 ⑧地图,用 A* 算 AGV-04 的路线
  │
  ▼ ⑥冲突消解:检查时间窗,发现路口K要等AGV-07 → ⑦交通管制协调
  │
  ▼ ⑩指令下发:通过 VDA5050 把节点序列发给 AGV-04
  │
  ▼ AGV-04 执行,⑪持续上报位置 → ⑨更新车队状态
  │
  ▼ 若 AGV-07 卡住 → ⑫故障容错 → 触发 ⑤⑥重算 → 新指令下发
  │
  ▼ AGV-04 到达 P12,任务完成,释放资源
🔑 三个关键观察
  • 几乎所有战术层模块都要查 ⑨车队状态、⑧地图——这两个是共享数据,是系统瓶颈点(L3-02 会讲)。
  • ⑥冲突消解依赖 ⑤路径规划的结果,但又会反过来修改它——这是战术层最复杂的耦合。
  • 整条链路是个闭环:指令下发后,状态上报回来,可能触发重规划。这就是 L3-02 的「滚动重规划」循环。

这 12 个模块怎么对应到 L1~L5

现在你知道了,本课程 L1~L5 本质就是在逐个吃掉这 12 个模块:

阶段主要攻克的模块
L1 单机⑧地图、⑤路径规划(单车)、底盘运动学约束
L2 多机核心④任务分配、⑥冲突消解(MAPF/CBS)、⑦死锁防护
L3 工程化①②③编排、⑨状态、⑩⑪通信(VDA5050)、⑫容错 + 整体架构
L4 拓展把这套架构迁移到 MRS、人形(⭐你的核心)、群体智能
L5 实战把 12 个模块集成成一个能跑的系统

人形调度:这张图会怎么变(预告)

既然你在做人形,提前告诉你:上面这张「AGV 调度全景图」到了人形,骨架不变,但有四个模块会膨胀或变形:
  1. ②任务编排:从"搬运编排"升级为"技能编排(Skill Orchestration)"——这是最大的变化,人形调度本质是技能工作流引擎。
  2. ⑤路径规划:从 2D 平面路径,升级为"全身运动规划"(几十个关节)。
  3. ⑧地图:从 2D 拓扑图,升级为"3D + 语义地图"(知道哪是桌面、哪是抽屉、手能伸到哪)。
  4. ⑫容错:从"停车等人",升级为"自主恢复"(跌倒自起、卡住脱困)。
其他模块(④分配、⑥冲突消解、⑦死锁、⑨状态、⑩⑪通信)的原理可直接迁移。这就是为什么我们要把 AGV 这套学扎实——它是人形调度的地基,80% 的骨架可以复用。

小结

  • 调度系统 = 三层(战略/战术/执行)× 12 个模块,数据从上往下流、状态从下往上反馈,形成闭环。
  • 战术层(调度引擎)是主战场,其中 ⑥冲突消解(MAPF/CBS)技术含量最高。
  • 整张图本质是一个实时分布式后端——你的主场。差异只在"把服务实例换成会动的车,把网络路由换成带物理约束的路径"。
  • 这张图到人形,骨架不变,但 ②⑤⑧⑫ 四个模块会膨胀——L4-02 会专门讲怎么迁移。
