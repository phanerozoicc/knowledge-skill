L1-01 · 地图建模:把现实变成图

阶段 L1 单机能力 难度:入门(动手) 前置:L0-05 预计:50 分钟
🎯 这节课你将学会:看着一个仓库/工厂的平面图,能把它抽象成节点+边+边权的图,并用 Python 写出来。这是所有路径规划算法的前提——没有地图,就没有规划。本课是 L1 的第一课,也是你第一次动手写调度相关的代码。

问题:算法不认识"仓库"

Dijkstra、A* 这些算法很聪明,但它们只认识一样东西:图。它们不知道什么是货架、什么是通道、什么是叉车禁区。所以在让算法工作之前,我们必须先把现实世界翻译成算法认识的图。这个过程叫「地图建模」。

这就是数据建模——和你设计数据库 schema 一模一样。现实世界(订单、用户、商品)不能直接存进数据库,你要先抽象成表和字段。地图建模同理:现实仓库不能直接进算法,你要先抽象成节点和边。

两种建模思路

L0-05 提过栅格 vs 拓扑,现在展开讲清楚。这是你做地图建模的第一个、也是最重要的决策。

思路 A:栅格地图(Grid)

把空间切成大小相等的方格,每格是一个节点,相邻格子之间有边。通常用 0/1 矩阵表示:0=可走,1=障碍。

优点:精细,能表示任意形状障碍,适合局部避障。
缺点:节点极多(1000㎡ 仓库切成 20cm 格 = 25000 节点),算法慢。关键问题:很多节点是"无意义的空地",算法要在上面白白搜索。

思路 B:拓扑图(Topological)⭐ 工业主流

只在有意义的位置(路口、货架位、充电桩、停靠点)设节点,通道用边连接。

优点:节点少(几十到几百),算法快,结构清晰,符合 AGV「点对点搬运」的本质。
缺点:建图要人工标注关键点(或半自动),精细避障还要配栅格。

📌 工业实践:两者结合 绝大多数工业 AGV/AMR 系统都用双层:
  • 拓扑图做全局规划:从 N0 到 N10,用 A* 找出节点序列(快)
  • 栅格图做局部避障:在每两个节点之间,用栅格精细绕开临时障碍(准)
这就是「全局粗规划 + 局部细规划」的经典架构。本课先专注拓扑图(因为它更体现建模思想),栅格在 L1-04 A* 时会再用到。

拓扑图建模:四步法

看着一个真实仓库,怎么一步步变成图?这是你要练的技能:

第 1 步:识别"关键点"→ 节点

问自己:AGV 在哪些位置会停下来做某事?这些位置就是节点:

  • 路口(通道交汇处,要决策往哪走)
  • 任务点(货架前、拣货位、上料点——任务的起终点)
  • 资源点(充电桩、等待区、缓冲区)
  • 出入口(电梯口、门、月台)

第 2 步:识别"通道"→ 边

两个节点之间,AGV 能直接走过去(中途不停、不拐弯),就连一条边。

第 3 步:给边加权重

权重 = 走这条边的代价。最常见是物理距离,但也可以是:

  • 时间(考虑这段路限速不同)
  • <能耗(上坡段权重大)
  • 风险(人机混行区权重稍大,鼓励绕开)

第 4 步:决定有向/无向

问:这条通道能双向走吗?如果只能单向(比如窄通道、防死锁设计),就用有向边。

用 Python 写出来

现在把图画进代码。这就是 L0-05 讲过的「邻接表」——你应该觉得眼熟。

# map_model.py —— 一个最小的拓扑地图模型
# 用嵌套字典表示:每个节点 → {邻居: 边权}

warehouse_map = {
    "N0_入口":  {"N1_主通道中点": 5, "N4_充电桩": 2},
    "N1_主通道中点": {"N3_货架A": 8, "N2_货架B": 6},
    "N2_货架B": {"N1_主通道中点": 6},   # 双向,所以有回边
    "N3_货架A": {},                      # 单向终点,没有出边(死胡同设计)
    "N4_充电桩": {"N0_入口": 2},
}

def neighbors(node, graph):
    """返回某节点的所有邻居及边权 —— 后面所有算法都要用这个"""
    return graph.get(node, {})

# 测试一下
if __name__ == "__main__":
    for node in warehouse_map:
        print(f"{node} 的邻居: {neighbors(node, warehouse_map)}")

运行它,你会看到每个节点能去哪、代价多少。这就是地图模型的全部——没有黑魔法,就是一张表。

这张表就是你写过无数次的 service_dependencies 或 routing_table。调度的地图,本质上就是一张「物理空间的 routing table」。

进阶:动态权重(伏笔)

真实系统里,边权不是静态的。它会因为实时情况变化:

  • 拥堵:某段路车太多,临时加大权重,让后续车绕行
  • 封锁:某段路在维修,权重设为 ∞(等于删边)
  • 电量:对低电量车,上坡段的"能耗权重"更大
# 动态权重的简单实现:权重是个函数,不是固定值
def edge_weight(from_node, to_node, context):
    base = warehouse_map[from_node][to_node]          # 静态距离
    congestion = context.get_congestion(from_node, to_node)  # 实时拥堵系数
    blocked = context.is_blocked(from_node, to_node)   # 是否封锁
    if blocked:
        return float('inf')                            # 封锁 = 不可走
    return base * (1 + congestion)                     # 拥堵加成

# context 是个对象,封装了"当前世界的实时状态"
# 后面 L3-02 会讲这个 context 怎么由"状态上报"实时更新
🔑 关键设计思想 把权重从常量变成函数,是地图模型从"玩具"走向"工业级"的关键一步。它让同一张图能反映实时世界。这就是为什么 L0-03 全景图里,「⑨车队状态」要持续喂给「⑧地图管理」——实时状态会改变图的权重,进而改变规划结果。

人形伏笔:地图会变成什么样

你做人形,这张图会升级:
  • 从 2D 拓扑 → 3D + 语义地图:不只记"能走到哪",还要记"这是桌子(能放东西)、这是抽屉(能拉开)、这是把手(能抓)"
  • 可达性图(Reachability):不只"脚能走到",还有"手能伸到哪"——人形有手臂,工作空间是 3D 的
  • 语义节点:节点不只是位置,还带属性(咖啡机、门、沙发),供技能编排使用
但底层还是图,还是邻接表,还是 A*。你学的拓扑建模能力直接可迁移,只是节点和边的语义更丰富。这是 L4-02 会深挖的点。

小结

  • 算法只认图,所以第一步是把现实建模成图(类比数据库 schema 设计)。
  • 两种思路:栅格(精细但慢)、拓扑(稀疏但快);工业实践是拓扑做全局 + 栅格做局部。
  • 拓扑建模四步:识别关键点→节点、识别通道→边、加边权、决定有向/无向。
  • 代码实现就是邻接表(一张字典),和你写的路由表/依赖图同构。
  • 动态权重(权重变函数)是走向工业级的关键——让图能反映实时世界。
