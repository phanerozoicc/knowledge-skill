L1-02 · 搜索算法入门:BFS / DFS

阶段 L1 单机能力 难度:入门(动手) 前置:L1-01 预计:50 分钟
🎯 这节课你将学会:亲手实现并运行两个最基础的图搜索算法——BFS(广度优先)和 DFS(深度优先)。它们本身在调度里用得少,但它们是 Dijkstra 和 A* 的亲爹。理解了它们"怎么走、为什么慢、为什么不够好",你下一课才能真正理解 Dijkstra 在改进什么。
📌 为什么先学"笨办法" 直接学 A* 你也能记住公式,但会知其然不知其所以然。BFS/DFS 是认知脚手架——它们暴露了"朴素搜索的痛点",而 Dijkstra/A* 的每个设计都是对这些痛点的回应。学完这课,你会带着"那怎么改进呢"的好奇心进入 L1-03。

graph = {

    "货架1": {"岔口A": 4},

    "货架3": {"岔口B": 7, "货架2": 3},
}

注意:这张图是带边权的。但 BFS 和 DFS 会故意忽略边权——这是它们的关键局限,等会儿你会看到后果。

BFS:广度优先,像水波扩散

核心思想:从起点出发,先访问所有距离为 1 的邻居,再访问距离为 2 的,一层层往外扩。像往水里扔石头,波纹一圈圈扩散。

BFS 就是你后端熟悉的消息广播层层扩散——比如一个事件从服务 A 发出,先到直接依赖 A 的服务,再到依赖它们的 service,逐层传播。或者像 BFS 遍历关注关系:先看你的直接关注,再看他们的关注。

BFS 怎么实现:用队列(Queue)

关键数据结构:队列(FIFO)。先把起点放进队列,然后循环:从队列取一个节点→访问它→把它的没访问过的邻居放进队列。直到队列空。

from collections import deque

def bfs(graph, start, goal):
    """最朴素的 BFS:只找'能不能到',先不记路径"""
    queue = deque([start])           # 队列,先进先出
    visited = {start}                # 记录已访问,防重复
    order = []                       # 记录访问顺序,方便观察

    while queue:
        node = queue.popleft()       # 取队首
        order.append(node)
        print(f"访问: {node}")

        if node == goal:
            print(f"🎉 找到 {goal}!")
            return order

        for neighbor in graph.get(node, {}):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)

    print(f"没找到 {goal}")
    return order

亲手跑一下:追踪 BFS 的执行

假设我们要从「入口」找「货架3」。下面是 BFS 一步步干了什么(请对照上面的图和代码看):

初始 队列=[入口], visited={入口} 第1轮 取出 入口 → 邻居{主道} 入队 队列=[主道], visited={入口,主道} 第2轮 取出 主道 → 邻居{入口(已访问),岔口A,岔口B} 入队 队列=[岔口A,岔口B], visited={+岔口A,岔口B} 第3轮 取出 岔口A → 邻居{主道(已),货架1} 入队 队列=[岔口B,货架1] 第4轮 取出 岔口B → 邻居{主道(已),货架2,货架3} # 货架3 就是目标!但它还没被"访问",只是入队 队列=[货架1,货架2,货架3], visited={+货架2,货架3} 第5轮 取出 货架1 → 邻居{岔口A(已)} 无新 第6轮 取出 货架2 → 邻居{岔口B(已),货架3(已)} 无新 第7轮 取出 货架3 → 是目标!🎉 找到

注意一个关键点:BFS 找到了「入口→主道→岔口B→货架3」,这是步数最少(3 步)的路。BFS 保证这一点——在无权图上,BFS 找到的就是步数最少的路。这就是它最大的优点。

DFS:深度优先,一条路走到黑

核心思想:从起点出发,随便挑一个邻居深入,一直深入到没法再深入(撞墙或已访问),再回退到上一个分叉,换条路继续深入。像走迷宫,贴着墙一直走。

DFS 就是你后端熟悉的调用栈——一个函数调用另一个,层层深入,最深的先返回。或者像递归遍历嵌套 JSON:一头扎到最深的叶子,再逐层退回。

DFS 怎么实现:用栈(Stack)

关键数据结构:栈(LIFO)。和 BFS 唯一的区别就是:取节点时从另一端取(后进先出)。

def dfs(graph, start, goal):
    """最朴素的 DFS:用栈代替队列"""
    stack = [start]                  # 栈!后进先出
    visited = {start}
    order = []

    while stack:
        node = stack.pop()           # 取栈顶(后进先出)
        order.append(node)
        print(f"访问: {node}")

        if node == goal:
            print(f"🎉 找到 {goal}!")
            return order

        for neighbor in graph.get(node, {}):
            if neighbor not in visited:
                visited.add(neighbor)
                stack.append(neighbor)

    print(f"没找到 {goal}")
    return order
🔑 本课最重要的一个观察 BFS 和 DFS 的代码几乎完全一样!唯一区别:数据结构从「队列」换成「栈」。就这一处改动,行为从"层层扩散"变成"一条路走到黑"。

这意味着什么?搜索算法的本质,就是"按什么顺序扩展节点"。BFS 用队列→优先扩展浅层;DFS 用栈→优先扩展深层。后面 Dijkstra 用"按代价排序的队列",A* 用"按 f=g+h 排序的队列"——都是同一个框架,只是换了个"排序规则"。抓住这一点,你就抓住了所有路径规划算法的骨架。

它们为什么不够好(为下一课铺垫)

BFS/DFS 能找到路,但有两个致命问题,正是这两个问题逼出了 Dijkstra 和 A*:

问题 1:BFS 忽略边权 → 找到的可能不是"最省钱"的路

回到我们的图。BFS 说「入口→主道→岔口B→货架3」最优(3 步)。但算算代价:

BFS 选的路:  入口→主道(5)→岔口B(6)→货架3(7)   总代价 = 18
另一条路:    入口→主道(5)→岔口B(6)→货架2(2)→货架3(3)   总代价 = 16

看!虽然多走一步,但总代价反而更低(16 < 18),因为货架2到货架3很近。BFS 因为只数步数不看代价,错过了更优的路。这就是为什么我们需要 Dijkstra——它按累积代价排序,而不是按步数。

问题 2:在真实大图上太慢

BFS 在我们 7 节点的小图上飞快。但想象一个 500 节点的真实仓库:BFS 要把大量"和目标完全无关"的节点都扩散一遍。它没有"往目标方向使劲"的直觉。这就是 A* 要解决的——加一个启发函数,让搜索"聪明地往目标靠"。

亲手跑一次,你会发现 DFS 的访问顺序"跳跃感"很强(一头扎进去),而 BFS 是"均匀扩散"。这种体感对理解下一课的 Dijkstra 至关重要。

小结

  • BFS(队列,层层扩散)保证在无权图上找到步数最少的路。
  • DFS(栈,一条路走到黑)快但不保证任何最优性。
  • 两者代码几乎一样,只差数据结构——搜索算法的本质就是"按什么顺序扩展节点"。
  • BFS/DFS 的两大痛点:① 忽略边权,可能错过代价更低的路;② 没有方向感,大图上太慢。
  • 这两个痛点分别由 Dijkstra(按代价排序)和 A*(加启发函数)解决——下一课的主角。
