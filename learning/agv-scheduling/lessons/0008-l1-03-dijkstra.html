L1-03 · 单车路径规划:Dijkstra 算法

阶段 L1 单机能力 难度:中等(动手) 前置:L1-02 预计:60 分钟
🎯 这节课你将学会:亲手实现并理解 Dijkstra 算法——它解决 L1-02 留下的痛点「BFS 忽略边权,错过代价更低的路」。你会看到 Dijkstra 其实就是把 BFS 的普通队列换成「按累计代价排序的优先队列」,加上一个叫「松弛」的新动作。学完这课,你能在一个带权图上,找出从起点到任意点的累计代价最小的路径。

Dijkstra 的核心:一招之差

上一课你已经知道:搜索算法的本质是"按什么顺序扩展节点"。现在请这样理解 Dijkstra:

Dijkstra = BFS,但把「先进先出队列」换成「按累计代价排序的优先队列」。

算法用什么结构按什么顺序扩展节点
BFS普通队列(FIFO)谁先入队谁先出 → 按步数(层级)
Dijkstra优先队列(按 g 排序)累计代价 g 最小的先出
A*(下一课)优先队列(按 f=g+h)f 最小的先出(加方向感)

就这一处改动,BFS 从"找步数最少"升级成"找累计代价最小"。这就是 Dijkstra。

Dijkstra 就是网络路由协议 OSPF 的核心。每个路由器用 Dijkstra 算"到其他网络的最短(代价最低)路径",代价就是链路的 metric(带宽/延迟)。你天天用的互联网,路由表就是这么算出来的。所以你不是在学新东西,你在学互联网路由背后的算法。

唯一的新概念:松弛(Relaxation)

Dijkstra 相比 BFS,除了换队列,只多了一个动作,叫松弛。这是整节课唯一需要认真理解的新东西。

松弛是什么

想象你对每个节点维护一个「当前已知的到它的最小代价」,记作 g[node]。一开始除了起点(g=0),其他都是 ∞(未知)。

当你从节点 u 探索到它的邻居 v 时,你发现了一条可能更短的路:g[u] + 边权(u,v)。如果这个值比 g[v] 当前记录的小,就更新 g[v]。这个"试试能不能更新得更小"的动作,就叫松弛。

# 松弛操作的伪代码 —— 就这么几行
def relax(u, v, edge_weight):
    if g[u] + edge_weight < g[v]:      # 发现更短的路?
        g[v] = g[u] + edge_weight       # 更新!
        parent[v] = u                   # 记住"从哪来的",用于回溯路径
        # 把 v 以新的 g 值放进优先队列,等会儿可能再扩展它
🔑 为什么叫"松弛" 想象 g[v] 是一根绷紧的弦,代表"目前知道的到 v 的代价"。每发现一条更短的路,弦就松一点(代价降一点)。当没有更短的路可发现时,弦彻底松弛下来,g[v] 就到了最优值。这个物理直觉比死记定义有用得多。

完整 Dijkstra(带可跑代码)

现在把"优先队列 + 松弛"拼起来,就是完整的 Dijkstra。下面这段代码你可以直接跑:

# dijkstra.py
import heapq

def dijkstra(graph, start, goal):
    """
    graph: 邻接表,{节点: {邻居: 边权}}
    返回:(最短代价, 路径列表)
    """
    g = {start: 0}                  # g[node] = 起点到 node 的已知最小代价
    parent = {start: None}          # 用于回溯路径
    pq = [(0, start)]               # 优先队列:(累计代价, 节点),堆自动按代价排序
    visited = set()

    while pq:
        cost_u, u = heapq.heappop(pq)   # 取出当前累计代价最小的节点

        if u in visited:                # 已经处理过,跳过(可能有旧的高代价副本)
            continue
        visited.add(u)

        if u == goal:                   # 找到目标,回溯路径
            path = []
            node = goal
            while node is not None:
                path.append(node)
                node = parent[node]
            return cost_u, path[::-1]   # 反转,从起点到终点

        # 对每个邻居做松弛
        for v, w in graph.get(u, {}).items():
            new_cost = cost_u + w       # 经过 u 到 v 的代价
            if v not in g or new_cost < g[v]:   # 松弛条件:发现更短
                g[v] = new_cost
                parent[v] = u
                heapq.heappush(pq, (new_cost, v))

    return None, []  # 不可达

对照 L1-02:看到 Dijkstra 赢在哪了吗?

🎉 这就是 Dijkstra 的威力 L1-02 里 BFS 找的路是「入口→主道→岔口B→货架3」,代价 18(3 步)。
Dijkstra 找的路是「入口→主道→岔口B→货架2→货架3」,代价 16(4 步)。

多走一步,但总代价更低! 因为 Dijkstra 在第 6 轮通过松弛发现了"绕经货架2更便宜"这个事实。BFS 永远发现不了,因为它不看代价。这就是"按累计代价排序"vs"按步数"的本质差距。

为什么 Dijkstra 能保证最优?

这是 Dijkstra 最神奇的特性,我用一句话给你讲透,不用数学证明:

因为它总是先扩展"累计代价最小"的节点。 所以当一个节点第一次被弹出(被"确定")时,它的 g 值已经不可能再被任何后来的路超越了——因为任何后来的路都必须经过一个"当前代价更大"的节点,加边只会更大。

这就是单调性。类比:你从公司开车回家,如果你总是先探索"距离最近的路口",那么你第一次到达家门口时,记录的距离一定是全局最短——因为任何绕远路都只会让你累计更远。

Dijkstra 的局限(为 A* 铺垫)

Dijkstra 解决了"忽略边权"的问题,但没解决"没有方向感"的问题。看这张图:

起点 S ──────────── 目标 G ↑ │ 向四面八方搜索,Dijkstra 会把整个图都翻一遍 │ 哪怕目标明显在右边,它也会先去探索左边 ↓ (大片无关区域)

Dijkstra 是无方向的——它不知道目标在哪,只能老老实实按代价从小到大全图扩散。在大地图上,它会搜索大量和目标无关的区域,浪费计算。

这就是 A* 要解决的:加一个启发函数 h,给搜索一个"往目标方向使劲"的方向感。下一课 L1-04 就是它。

人形伏笔

Dijkstra 在人形/具身里依然是基础工具,但有两个升级方向:
  • 配置空间(Config Space):人形不是 2D 点,它的"状态"是几十个关节角度的组合。在这个高维空间里跑 Dijkstra,搜索会爆炸——这是为什么需要 A* 和 RRT(L1-06)。
  • 多目标代价:人形的"代价"不只是距离,还有能耗、稳定度、避让人。代价函数变复杂,但 Dijkstra 框架不变。
所以 Dijkstra 是地基,人形是在地基上换"更复杂的图和代价函数"。

小结

  • Dijkstra = BFS + 把队列换成「按累计代价排序的优先队列」+ 松弛操作。
  • 松弛:发现到某节点更短的路时,更新它的 g 值和来源。
  • Dijkstra 保证最优:因为它总先扩展代价最小的节点,第一次弹出即最优。
  • 解决了 BFS 忽略边权的痛点(L1-02 案例:代价 18 → 16)。
  • 未解决的痛点:无方向感,大图上全图扩散,浪费——这是 A* 要解决的。
