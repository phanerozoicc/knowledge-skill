L1-04 · 单车路径规划:A* 算法(工业标配)

阶段 L1 单机能力 难度:中等(动手) 前置:L1-03 预计:60 分钟 ⭐ 工业核心
🎯 这节课你将学会:实现并理解 A* 算法——它是工业 AGV/AMR 系统里单车路径规划的事实标准。你会发现 A* 只是给 Dijkstra 加了一个"方向感"(启发函数 h),改动极小但效果惊人。学完这课,你就掌握了单车路径规划的完整武器库,可以开始进 L2(多机)了。

A* 的核心:给 Dijkstra 加方向感

上一课结尾,Dijkstra 留下一个痛点:它没有方向感。目标明明在东边,它却往西边也搜,白白浪费计算。A* 解决的正是这个问题。

A* = Dijkstra,但排序时不仅看"已经花了多少代价(g)",还加上"估计到目标还要多少代价(h)"。

排序规则从 g 变成 f = g + h。就这一处改动。

算法排序依据含义
Dijkstrag(已花代价)"谁目前累计代价小,先扩展谁"
A*f = g + h"谁预计总代价小,先扩展谁" → 优先扩展"既便宜又靠近目标"的

三个字母的含义,这是 A* 全部的理论:

  • g(n):从起点到 n 的已知代价(实测的,精确)
  • h(n):从 n 到目标的估计代价(猜的,启发函数)
  • f(n) = g + h:预计的总代价,排序用这个
A* 就是你做带业务直觉的搜索。
  • Dijkstra ≈ 老老实实 BFS,把所有可能性同等对待,像新手工程师排查 bug 没方向地乱看。
  • A* ≈ 资深工程师排查 bug,有经验直觉:"问题大概率在数据库层",先去那里看(h 小),而不是平均用力。
h 就是那个"经验直觉"。它让搜索优先往目标方向使劲,而不是无方向扩散。

启发函数 h:成败的关键

A* 的全部魔法,都藏在 h 怎么设计。这是 A* 唯一的难点,我给你讲透。

h 怎么算:几何距离

最常见:用 n 到目标的几何距离作为 h。因为现实中,两点间直线距离是"最少还要走多远"的下界——你不可能比直线更短。

可采纳性(Admissibility):A* 保证最优的前提

这是 A* 最重要的一个性质,一句话:

只要 h(n) ≤ 真实剩余代价,A* 就保证找到最优解。 这叫 h 是「可采纳的」。

🔑 直觉:为什么不能高估 h 是"乐观估计"。如果 h 高估(悲观,觉得"还很远"),f=g+h 就被带偏,可能优先扩展错误的方向,导致找到次优解甚至绕远路。

几何距离天生可采纳——因为"直线距离"一定是真实最短路的下界(不会比真实还远)。所以用几何距离做 h,A* 既快又保证最优。这是工业标配的原因。
h 的大小效果结果
h = 0没有方向感退化成 Dijkstra(慢但最优)
0 < h ≤ 真实有方向感且乐观✅ 又快又最优(理想)
h > 真实方向感过强(贪婪)更快,但可能次优
h = 真实完美预知直接走最优路,零浪费(理论极限)
⚠️ 工程取舍:贪婪 A* 有时候工业上故意让 h 稍微高估,换取速度,接受一点点次优。这又回到 L0-05 的「最优解 vs 可行解」——在实时场景下,"快 10 倍但代价多 5%" 经常完胜。这叫 weighted A*。L2 多车场景下会常用。

A* 完整代码(和 Dijkstra 对比着看)

准备好了——你会看到 A* 的代码和 Dijkstra几乎一模一样,只多了两行。这是本课最该记住的事实。

# astar.py
import heapq
import math

def heuristic(a, b):
    """启发函数:两点间欧几里得距离。
    注意——这里需要节点的坐标,所以图里每个节点要带 (x,y)。
    下面 positions 是额外加的坐标信息。"""
    ax, ay = positions[a]
    bx, by = positions[b]
    return math.hypot(bx - ax, by - ay)

def astar(graph, start, goal):
    g = {start: 0}
    parent = {start: None}
    # ★ 唯一改动 1:优先队列按 f = g + h 排序,而不是 g
    pq = [(heuristic(start, goal), start)]
    visited = set()

    while pq:
        f_u, u = heapq.heappop(pq)      # f 最小的先出

        if u in visited:
            continue
        visited.add(u)

        if u == goal:
            path = []
            node = goal
            while node is not None:
                path.append(node)
                node = parent[node]
            return g[goal], path[::-1]

        for v, w in graph.get(u, {}).items():
            new_g = g[u] + w
            if v not in g or new_g < g[v]:
                g[v] = new_g
                parent[v] = u
                # ★ 唯一改动 2:推入堆时用 f = new_g + h,而不是 new_g
                f_v = new_g + heuristic(v, goal)
                heapq.heappush(pq, (f_v, v))

    return None, []
🔑 看清楚了吗 相比 L1-03 的 Dijkstra,A* 的代码只改了两行(标 ★ 的):初始堆用 h、推入堆用 f=g+h。其余一模一样。这就是为什么说"搜索算法都是同一个框架,只是换排序规则"。你已经掌握的 Dijkstra 知识,99% 都适用于 A*。

一个工程细节:A* 需要坐标

注意 A* 比 Dijkstra 多需要一样东西:每个节点的物理坐标 (x,y),用来算 h。所以我们的地图模型要扩展:

# 扩展地图:除了邻接表,还要有节点坐标(用于算启发函数)
graph = {
    "入口":  {"主道": 5},
    "主道":  {"入口": 5, "岔口A": 3, "岔口B": 6},
    "岔口A": {"主道": 3, "货架1": 4},
    "岔口B": {"主道": 6, "货架2": 2, "货架3": 7},
    "货架1": {"岔口A": 4},
    "货架2": {"岔口B": 2, "货架3": 3},
    "货架3": {"岔口B": 7, "货架2": 3},
}

# ★ 新增:每个节点的物理坐标(米)
positions = {
    "入口":  (0, 0),
    "主道":  (5, 0),
    "岔口A": (5, 3),
    "岔口B": (11, 0),
    "货架1": (5, 7),
    "货架2": (11, 2),
    "货架3": (14, 2),    # 货架3 在最右边
}
这就是给数据模型加字段。Dijkstra 只需要邻接表(像只有外键的关系);A* 还需要每个节点的坐标(像加了个 latitude/longitude 字段)。地图建模的复杂度只多了一点点。

人形伏笔

A* 在人形里依然核心,但有两个升级:
  • 启发函数变难:2D 地图里 h 就是欧几里得距离,简单。但人形是几十个关节的高维空间,"到目标的距离"很难定义——这就是为什么高维规划常换用 RRT(L1-06)。
  • 加权 A* 更常用:人形规划成本极高,工业上常用 weighted A*(故意高估 h)换速度,接受次优。这呼应 L0-05 的"最优 vs 可行"。
但"带方向感的搜索"这个思想,A* 到 RRT 一脉相承。地基不变。

小结

  • A* = Dijkstra + 启发函数 h。排序从 g 变成 f = g + h。代码只差两行。
  • h 是"到目标的乐观估计",常用几何距离。
  • 可采纳性:h ≤ 真实剩余代价时,A* 保证最优。几何距离天生可采纳。
  • 同样最优结果,A* 比 Dijkstra 扩展更少节点(有方向感)→ 工业标配。
  • 工程取舍:weighted A*(故意高估 h)牺牲最优换速度,实时场景常用。
