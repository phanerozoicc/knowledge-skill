L1-06 · RRT 与采样规划(进阶)

阶段 L1 单机能力 · 收尾 难度:进阶 前置:L1-04(A*), L1-05 预计:50 分钟 ⭐ 人形关键
🎯 这节课你将学会:理解什么时候 A* 会失效,以及为什么需要换一种完全不同的思路——采样规划。你会掌握 RRT 的核心思想(随机撒点 + 向点生长),并理解它为什么是人形/机械臂这种高自由度机器人的主力规划工具。这课是 L1 的收尾,也是直接通向 L4-02 人形全身运动规划的桥梁。

先问:A* 不是挺好吗,为什么还要别的?

L1-03、L1-04 你已经掌握:Dijkstra、A* 都是工业标配。那为什么还需要 RRT?答案在一个词:维度灾难(Curse of Dimensionality)。

回顾:A* 工作在什么上

A* 工作在图上——节点是离散的、数量有限的。我们的实验台地图 7 个节点,A* 秒解。即使是栅格地图,一个仓库也就几万个格子,A* 也能跑。

关键问题:格子数 = 维度的指数。维度越多,格子数爆炸。

维度灾难:一个让你后背发凉的算术

场景"状态"是什么维度格子数(每维 10 档)
2D 仓库 AGV(x, y)2 维10² = 100
带朝向的 AGV(x, y, θ)3 维10³ = 1,000
6 轴机械臂6 个关节角6 维10⁶ = 1,000,000
7 自由度机械臂7 个关节角7 维10⁷ = 10,000,000
人形(全身)几十个关节30+ 维10³⁰ ≈ 宇宙原子数
⚠️ 这就是 A* 失效的地方 A* 要把空间切成格子搜索。但在 30 维空间里,格子数比宇宙原子还多——你永远切不完、搜不完。这不是"算法慢一点",是"根本不可能"。A*/Dijkstra 这类基于网格的搜索,在高维空间里彻底失效。

这就是为什么需要一种不依赖网格的全新思路。
维度灾难在后端你其实见过类似的:组合爆炸。比如权限系统,3 个角色 × 4 个资源 × 5 个动作 = 60 种组合,还能枚举;但如果是"为每个用户、每个资源、每个时间窗、每个 IP 段配置规则",维度一多,规则空间立刻爆炸,你只能用 RBAC/ABAC 这种不枚举、按需求值的方式。RRT 之于路径规划,就像 ABAC 之于权限:不穷举空间,而是按需采样。

RRT 的核心思想:不搜格子,撒点

RRT(Rapidly-exploring Random Tree,快速探索随机树)的核心思想一句话:

不要把整个空间切成格子慢慢搜;改成在空间里随机撒点,每撒一个点,就从已有的树上往它伸一小段。 撒得多了,树就铺满了空间,总有一天会碰到目标。

RRT 的四步循环

RRT 的算法极其简单,就是一个循环,每次四步:

def rrt(start, goal, space, step_size, max_iter):
    tree = [start]                        # 树,初始只有起点
    for i in range(max_iter):
        # 第1步:在空间里随机撒一个点 q_rand
        q_rand = random_sample(space)

        # 第2步:在树里找离 q_rand 最近的节点 q_near
        q_near = nearest(tree, q_rand)

        # 第3步:从 q_near 朝 q_rand 方向,走一小段 step_size,得到 q_new
        #        (中途若撞障碍,丢弃这次)
        q_new = steer(q_near, q_rand, step_size)
        if not collision_free(q_near, q_new):
            continue

        # 第4步:把 q_new 加进树,记下它的父节点是 q_near
        tree.append(q_new)
        parent[q_new] = q_near

        # 如果 q_new 离 goal 够近了,成功!
        if distance(q_new, goal) < threshold:
            return reconstruct_path(q_new)
    return None  # 达到最大迭代还没找到
🔑 RRT 的精髓 它从不试图"理解"整个空间,只做局部生长。 每次随机一个方向,迈一小步。这种"盲但便宜"的策略,让它能在任何维度空间里跑——因为每一步的成本不随维度爆炸(不像 A* 要切格子)。这就是它对付维度灾难的法宝。

为什么"乱撒点"反而有效?

听起来 RRT 像"瞎走",但它有两个巧妙之处,让它快速覆盖大空间:

  1. 偏向未探索区域:因为每次朝"随机点"生长,而未探索的空旷区域更容易被随机命中(那里面积大),所以树天然地往空白处扩,而不是在已探索区域原地打转。这就是名字里"快速探索(Rapidly-exploring)"的由来。
  2. 概率完备性:只要路存在,迭代次数足够多时,找到路的概率趋于 1。严格说是"趋于确定",不是有限步内"一定",但工程上可当作"多撒点总能找到"。注意:是"能找到",不保证"最优"。

RRT* :从"能找到"到"找得好"

RRT 有个明显缺点:找到的路通常很绕、很丑(因为是随机生长的)。RRT* 是它的升级版,加了一步"重新连接":每加一个新节点,检查能不能让附近的节点通过新节点走得更短,从而不断优化整棵树。

RRTRRT*
找到路✅ 快✅ 慢一点
路的质量❌ 通常很绕✅ 渐近最优(越跑越优)
何时用实时、只要可行解离线、要高质量路径
💡 和 A* 的取舍对比
  • A*:低维(2D/3D),保证最优,但要切格子
  • RRT:高维,不保证最优,但不切格子、能跑
  • RRT*:高维,渐近最优,但慢
工业实践常常混合:用 RRT 快速找一个可行解,再用轨迹优化(L1-05 提过)把它平滑成高质量的。这叫"采样规划 + 轨迹优化"两段式。

为什么这课对人形是关键(重点)

你做人形,这课的重要性可能超过 A*:
  • AGV 是 2~3 维(位置 + 朝向)→ A* 完美胜任,RRT 用不上。
  • 机械臂是 6~7 维(每个关节一个角)→ A* 开始吃力,RRT 成为主力。
  • 人形全身是 30+ 维(双腿+双臂+躯干+头,几十个关节)→ A* 彻底不可能,RRT(及其变体)是少数能跑的工具之一。
而且人形的"空间"不是物理 xyz 空间,是关节角度空间(Configuration Space / C-space)——每个维度是一个关节能转的角度。RRT 在这个抽象的高维空间里撒点生长,找到的就是"各关节该怎么动才能从姿态 A 到姿态 B"。

配置空间(C-space):一个必须懂的概念

这是 RRT 真正工作的地方,我简单讲透(这是人形/机械臂的核心概念):

配置空间(C-space):把机器人的所有可能姿态表示成一个多维空间,每个维度是一个自由度(关节角)。机器人的一个"姿态"= C 空间里的一个"点"。

机器人C 空间的维度"一个点"代表
2D AGV2~3 维 (x,y,θ)车在 (3,5) 朝向东
6 轴机械臂6 维6 个关节各自的角度组合
人形30+ 维全身几十个关节的角度组合

RRT 撒的"点",撒的就是这种姿态空间里的点——"机械臂各关节转到某组角度"。规划出来的"路",就是"各关节角度怎么连续变化"。这就是为什么 RRT 能搞定人形:A* 在这里会爆炸,而 RRT 不管维度多少,每步成本都低。

小结

  • A* 这类网格搜索在高维空间(机械臂、人形)会遭遇维度灾难,彻底失效。
  • RRT 的核心:不切格子,在空间随机撒点 + 向点生长,每步成本不随维度爆炸。
  • RRT 概率完备(能找到),但路通常绕;RRT* 渐近最优(越跑越优),但慢。
  • 人形/机械臂的规划在配置空间(C-space)里进行——"姿态空间",维度 = 自由度数。
  • 工业实践:RRT 找可行解 + 轨迹优化平滑,是高维规划的标配两段式。
