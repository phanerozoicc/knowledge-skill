L2-02 · 冲突的本质与分类

阶段 L2 多机调度核心 难度:中高 前置:L2-01, L1-05 预计:55 分钟
🎯 这节课你将学会:把"多车会撞"这个模糊感觉,变成可分类、可检测、可消解的形式化问题。你会掌握冲突的五种类型、支撑检测的核心数据结构预留表(你之前独立推导过的那个),以及为什么"各自 A*"必然撞车。这课是 L2-04(CBS)的直接前奏。
在 L1-05,你曾反驳我:"在碰撞检测或空间锁闭中,还是要轨迹才能锁定对应空间"。这课就是你那个洞察的正式版本——你说的"空间锁闭",在这里叫预留表(Reservation Table),是冲突检测的核心数据结构。你已经摸到了门口,现在我们正式进门。

为什么"各自 A*"必然撞车

一个自然的想法:既然 A* 能给单车找最优路径,那让每台车各自跑 A*不就行了?这是新手方案,也是注定失败的方案。看为什么:

关键:两台车各自规划时,谁也不知道对方的存在。V1 的 A* 看到"路口 K 是空的"(因为 V2 还没规划),V2 的 A* 也看到"路口 K 是空的"。都以为安全,结果同时刻到达 → 撞。

这就是并发写同一行数据的经典问题。两个事务都读到"余额=100"(因为对方还没写),各算各的,都写回"余额=80"——丢了更新。各自 A* 的撞车,和多事务并发写是同一个病:没有协调,基于陈旧状态做决策。后端靠锁解决,调度靠预留表解决。

预留表:你的"空间锁闭"的正式版本

你说的"锁定对应空间",精确机制是这样:每台车规划好路径后,把"我在何时占用何地"登记到一张共享表里。后来的车规划时,必须查这张表避开已占用的时空。

预留表(Reservation Table):一张 (空间单元, 时间段) → 车辆 的映射表。它记录"未来谁占了哪段路的哪个时段"。任何新车规划路径时,必须保证它的时间-空间占用不和表里已有项冲突。

空间单元时间段占用车辆
路口Kt=10s ~ 12sV1
路段 主道-岔口Bt=8s ~ 10sV1
路口Kt=11s ~ 13s⚠️ V2 想占,但和 V1 冲突!
预留表就是一张带时间维度的行锁表。后端的 SELECT FOR UPDATE 锁的是"某行现在";预留表锁的是"某段路 + 某个未来时间段"。所以它是 4D 锁(空间 2D/3D + 时间)。你之前说"空间锁闭",精确说是时空锁闭——这就是为什么 L1-05 我讲过"时间窗"必须由调度持有,不能委托给车载。

冲突的五种类型(必须全认得)

这是本课的核心干货。多车冲突不是笼统的"撞",而是五种不同的类型,每种有不同的检测和消解方式。认全它们,你才能看懂 L2-04 的 CBS 算法在处理什么。

📝 说明:不同文献/教材对冲突分类粒度不同(有的列 3 种,有的 5~6 种)。本课采用覆盖最全的 5 种分类——它包含了 MAPF 经典文献里所有冲突形态,你看别的资料时可能会看到合并表述(如把"迎面"并入"边冲突"),本质相同。

类型 1:节点冲突(Vertex Conflict)

两台车在同一时刻到达同一节点(路口/位置)。

类型 2:边冲突 / 对向冲突(Edge / Swapping Conflict)

两台车在同一时刻,沿同一条边相向而行(一个从 A→B,一个从 B→A)。它们会在边中间撞上,或者面对面卡住。

类型 3:跟随冲突(Following Conflict)

两台车沿同方向走同一条边,但后车比前车快,会追尾。或者前车在边末端停下,后车撞上来。

类型 4:迎面冲突(Head-on,广义对向)

和边冲突类似但更广义:不只是单条边上相向,而是在路口/区域里迎面相遇。处理上和边冲突相近,常合并讨论。

类型 5:终点冲突(Goal Conflict)

一台车已经到达它的终点(停在 P),另一台车的路径经过 P。停着的车成了障碍。

五种冲突速查

类型发生条件后端类比
节点冲突同时刻到同节点并发写同一行
边冲突(对向)同时刻同边相向双向同时写互斥资源
跟随冲突同向但后车更快消费速度不匹配背压
迎面冲突路口/区域迎面资源抢占
终点冲突停车的终点挡了别人僵尸实例占用资源

怎么检测:预留表 + 时空轨迹

回到预留表。检测冲突的流程是:

  1. 每台车规划好路径后,按预估速度算出时空轨迹(何时在哪个节点/边)
  2. 把时空占用登记进预留表
  3. 新车规划时,把它候选路径的时空占用和表里已有项比对,看是否有时空重叠
  4. 有重叠 → 检测到冲突,触发消解(L2-04 CBS)

那"时空轨迹"到底怎么算?(关键细节)

很多教材跳过这步,但它是你真正要做工程时必须会的。其实极简单——距离 ÷ 速度 = 时间,然后累加:

路径: 入口 --(5m)-- 主道 --(6m)-- 岔口B --(7m)-- 货架3
预估速度: v = 1.5 m/s(恒速简化)

到达时刻(累加 时间=距离/速度):
  入口:   t = 0
  主道:   t = 0   + 5/1.5 ≈ 3.3s
  岔口B:  t = 3.3 + 6/1.5 ≈ 7.3s
  货架3:  t = 7.3 + 7/1.5 ≈ 12.0s

→ 时空轨迹 = [(入口,0), (主道,3.3), (岔口B,7.3), (货架3,12.0)]
→ 填进预留表:节点"岔口B" 在 [7.3,12.0]s 被 V1 占用
这就是给路径算端到端时间线——和你给 API 调用链估算延迟一模一样:每段耗时(=距离)÷ 处理能力(=速度)= 该段耗时,累加成总时间线。预留表 = 一张"未来谁在何时占用哪个资源"的时间线表。
⚠️ 两个工程细节(L2-03/L3-02 展开)
  1. 速度是预估的,不是精确的。这就是 L1-05 提的耦合点:预估不准 → 时间窗不准 → 锁不准。工业上留安全余量(每段多加缓冲)+ L3-02 的滚动重规划持续修正。
  2. 节点占用算"停留时间"。车过路口会减速/转弯,占用不是瞬间。所以预留表里节点占用是时间段(比如 0.5s),节点冲突判断的是时间窗重叠,不是单点相等。
🔑 这就回答了你 L1-05 的问题 你当时问"空间锁闭不是要轨迹吗"。答案就在这:调度器持有的"轨迹"是时空轨迹(节点序列+时间窗),正是用来填预留表、做冲突检测的。它不需要运动学平滑那种细粒度轨迹——节点级的时间窗就够用于冲突检测。这是"调度用粗时空轨迹,车载用细运动学轨迹"的分界线。

小结

  • "各自 A*"必然撞车——因为各车基于陈旧状态决策,没有协调(=并发写问题)。
  • 预留表 = (空间, 时间段) → 车辆 的映射 = 你说的"空间锁闭"的正式版,本质是 4D 行锁。
  • 五种冲突类型:节点 / 边(对向) / 跟随 / 迎面 / 终点。认全才能看懂 CBS。
  • 检测靠"时空轨迹填预留表 + 新路径比对"。
  • 调度器持有的"轨迹"是节点级时空轨迹(够做冲突检测),不是运动学细轨迹。
