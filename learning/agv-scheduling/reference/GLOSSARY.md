# AGV / 机器人调度系统 术语表

本表是本工作区的**规范用语**。所有课程、练习、学习记录都遵循这里的术语。只有当学习者真正理解一个概念后,才把它加入这里——它是已压缩知识的记录,不是用来背的词典。

> 规则:术语只在学习者掌握后添加。随理解加深会原地更新,不保留过期定义。

## 核心问题与指标

**并发冲突**:
多个执行体(车/请求)在同一时刻争夺同一份有限资源,若不加协调必然发生的互相阻碍。是调度系统存在的根本理由。
_别名_:资源争用。_后端映射_:并发写同一行数据、热点 key。

**吞吐量 (Throughput)**:
单位时间内系统完成的任务数(任务/小时)。调度系统的核心正向指标之一。
_后端映射_:QPS / TPS。

**死锁**:
多个执行体形成环形等待(A 等 B、B 等 C、C 等 A),谁都无法推进,系统局部或整体卡死。
_别名_:交通死锁(车辆场景下的具体形态)。_后端映射_:数据库死锁、分布式锁死锁。
_注意_:在本工作区「死锁」默认指多车调度场景,与数据库死锁同源同构。

**空驶率 (Empty-run)**:
车辆空载移动距离占总移动距离的比例。越低越省能耗、越省时间。
_后端映射_:无效调用、资源空转开销。

## 系统结构(三层)

**调度引擎 (Scheduling Engine / 战术层)**:
调度系统的中间层,持续决定「哪台车干哪个活、走哪条路、互不冲突」。内含三件事:任务分配、路径规划、冲突消解。
_后端映射_:任务队列 + 调度器 + 负载均衡。

_注意_:「路径规划」是调度引擎内的一个子功能,**不是**这一层的名字。

## 移动机器人分类(L0-02)

**AGV (Automated Guided Vehicle,自动导引车)**:
走固定/预设路线、不自主避障、高度依赖中央调度的自动搬运车。简单可靠、单车便宜,改路线需改物理设施。
_后端映射_:静态路由 / 固定专线。

**AMR (Autonomous Mobile Robot,自主移动机器人)**:
用 SLAM 自建地图、实时自主规划路径、能自己绕障的移动机器人。灵活但单车贵、故障面大,智能部分下放车端。
_后端映射_:动态路由 + 服务发现。

**底盘运动学 (Kinematics)**:
决定机器人「能否原地转向、转弯半径多大、能产生什么形状路径」的物理属性。是路径规划的硬约束。
_主要构型_:差速(可原地转)、阿克曼(有转弯半径,如叉车)、全向/麦克纳姆(可横移)。
_注意_:本工作区后续提到「底盘」时统一指此概念。

**集中式架构 (Centralized)**:
所有决策智能(路径、避让、分配)都在中央调度系统,车只执行指令。典型 AGV 场景。
_对应_:分布式架构(智能下放车端)、混合式(常态车端自治+特殊区域中央接管)。三者构成调度架构的谱系。
_后端映射_:集中式≈单体服务;分布式≈微服务;混合式≈云边协同。

## 数学与算法语言(L0-05)

**图 (Graph)**:
由节点和边组成的数据结构,是调度算法的核心舞台。节点表示位置,边表示通道,边可带边权表示代价。有无向(双向)和有向(单向)之分。
_后端映射_:服务依赖图、ER 图、Git 提交图。

**边权 (Weight / Cost)**:
边上附带的数值,表示走过该边的代价(距离/时间/能耗)。同一图上,「最短时间路」和「最短能耗路」可能不同。
_别名_:代价。_注意_:本工作区「最短路」默认指边权之和最小,非几何最短。

**NP-hard**:
一类不存在已知快速(多项式时间)算法求最优解的问题。规模变大时求最优解的计算时间指数级爆炸。多车调度(MAPF)即属此类,是调度"无银弹"的根本原因。
_应对_:近似算法、启发式、分治、滚动重规划、松弛约束——与后端的缓存/最终一致/流处理/微服务拆分同构。

**近似算法 (Approximation Algorithm)**:
不追求最优解,在多项式时间内给出一个有质量保证(或经验上够好)的可行解的算法。工业调度的主力工具。
_对比_:精确算法(求最优,但可能不可计算)。_后端映射_:缓存(接受非最新)、布隆过滤器(允许假阳性)。
