L0-01 · 前端是什么:后端工程师的翻译课

阶段 L0 地基 难度:入门 前置:无 预计:35 分钟
🎯 这节课你将学会:用后端视角讲清三件事——前端到底是什么(领地边界在哪)、React 解决什么问题(为什么是 UI = f(state))、以及这门课在 AI 时代带你到哪一层。这是后面所有课的锚:迷路了就回到这一课。

一、重新定位:前端不是一个「页面」,是一个客户端系统

很多后端工程师对前端的印象停留在「切图、写页面、调样式」。学了就忘、忘了就烦,很大程度是因为这个定位是错的。更准确的一句话:

前端是运行在用户设备上的分布式系统客户端,浏览器是它的操作系统。

把浏览器当成一个「你已经部署到用户设备上的操作系统」,它提供的系统能力一眼看去非常眼熟:

浏览器提供像操作系统的什么你用过的对应物
JS 引擎(V8 等)计算 + 进程/线程调度(事件循环)JVM + 线程池
渲染引擎GUI 系统—(这是你的知识空白区,L1 的主战场)
fetch / HTTP网络栈HttpClient / OkHttp
localStorage / IndexedDB / Cache文件系统 + 本地数据库SQLite + 磁盘缓存
同源策略、沙箱权限与安全模型容器隔离、IAM
你写过后端服务,也写过调用后端的客户端(SDK、脚本、定时任务)。前端就是一个极其苛刻的富客户端:
  • 跑在你无法控制的设备上:不能 SSH 上去排查,只能靠埋点和日志遥测
  • 随时被「断电重启」:用户一刷新,所有内存状态归零——所以「什么状态放内存、什么放持久层」是前端的日常决策(L1/L2 反复出现)
  • 版本碎片化:不同浏览器 ≈ 不同的 OS 发行版,「兼容性」就是前端的 JDK 版本问题
还有一条最苛刻的 SLA:60fps 意味着每 16.7ms 要出一帧,超了用户就说「卡」。你对 P99 的敏感,在这里叫「掉帧」。

二、从一次点击到像素:领地划界

把一次完整的「用户看到页面并交互」展开,时间线上是这样的:

用户在地址栏输入 URL,回车
   │
   ├─ DNS 解析 → TCP 连接 → TLS 握手              ┐
   ├─ HTTP 请求穿过网络,打到后端                   │ 你熟悉的领地
   ├─ 网关 → 鉴权 → 业务逻辑 → 数据库              │ (本课程当黑盒)
   ├─ 响应返回:HTML(可能含服务端渲染的首屏)      ┘
   ▼
浏览器接管 ──────────────────────────────────────── 本课程的领地
   │
   ├─ 解析 HTML → DOM 树;解析 CSS → CSSOM
   ├─ 合成渲染树 → 布局(算几何)→ 绘制(出像素)
   ├─ 下载并执行 JS → 事件循环(event loop)接管
   ▼
用户点击按钮
   │
   ├─ 事件触发你写的处理函数
   ├─ 函数里 fetch 后端 API(又一次回到你的领地)
   ├─ 拿到 JSON → 更新状态 → 界面跟着变化
   ▼
用户看到新界面,循环继续

所以领地边界很清楚:后端工程师的领地是「请求进来之后到响应出去」;前端的领地是「响应到达用户设备之后的一切」——解析、渲染、事件、状态,以及下一次请求的发起。这也解释了前端性能问题的口味:大多不是「计算慢」,而是渲染多了、请求乱发、状态乱同步。

🔧 动手(30 秒,别跳过) 打开任意网页(比如 react.dev),按 F12 打开 DevTools → Elements 面板,随便展开、收起几个节点。你看到的这棵可折叠的树就是 DOM——L1 的所有故事都发生在它上面。以后每节课你都会开着这个面板。
🔑 关键洞察 整个课程其实只回答一个问题:「状态在哪里、怎么变、变了之后界面怎么跟着变」。L1 讲 React 怎么回答它,L2 讲状态多了怎么管,L3 讲把一部分状态搬回服务端(server-first)。记住这条主线,你就永远不会迷路。

三、React 解决什么问题:UI = f(state)

先看你学 JS 那个年代的典型写法(没有框架的「命令式」DOM 操作):

// 「添加一条待办」要亲手指挥每一步 DOM 操作:
button.addEventListener('click', () => {
  const li = document.createElement('li');
  li.textContent = input.value;
  list.appendChild(li);              // 1. 加列表项
  countEl.textContent = items.length + 1;  // 2. 别忘了同步计数
  emptyHint.style.display = 'none';  // 3. 别忘了藏掉"暂无待办"
  input.value = '';                  // 4. 别忘了清空输入框
});

状态只有一两个时没问题。当状态有十个、界面分支有几十个时,「状态」和「界面」的一致性就变成了手工维护的分布式事务——每改一处状态,都要人肉记得同步所有受影响的界面,漏一步就是「显示不同步」的 bug。

React 的回答是把这件事声明式化:

// 只描述「界面由什么决定」,不写「怎么更新它」:
function TodoList() {
  const [items, setItems] = useState([]);   // 状态
  return (
    <ul>
      {items.length === 0 && <li className="hint">还没有待办</li>}
      {items.map(t => <li key={t.id}>{t.text}</li>)}
      <span>共 {items.length} 条</span>
    </ul>
  );
}
// 添加待办 = 只改状态:setItems([...items, newTodo])
// 界面怎么更新?React 负责。

UI = f(state) —— 界面是状态的投影。

你只声明「界面长什么样由什么决定」;状态一变,React 重新执行组件函数,算出应该的新界面,把差异(diff)应用到 DOM。这个「重新执行 → 算差异 → 应用」的过程叫重渲染(re-render)——它是前端 80% 性能问题和 bug 的发源地,L1-02 会用一整节课讲它。

这是全课最重要的类比,记住它,React 就已经懂了一半:
  • React 之于 DOM ≈ 数据库视图之于基础表:你只改基础表(状态),视图(界面)自动跟着变,不手写同步
  • 声明式 ≈ K8s:你声明「期望 3 个副本」,控制器负责把现实拉到期望;而不是手写脚本一台台启停机器。React 就是界面的 K8s——你声明期望界面,React 负责把 DOM 拉到期望状态
  • 「状态变了自动重算、能少算就少算」≈ 缓存失效与命中策略:React 内部决定什么时候重算整个视图、什么时候复用(memo)——L3 性能课讲的就是怎么「调缓存参数」

四、AI 时代的学习契约:学到哪一层

你在第一节课之前问的问题,现在正式回答。AI 把「默写代码」的价值打掉了,但把「判断代码」的价值抬高了。所以深度分三条线:

层级你能做到什么后端类比本课程对应
及格线看得懂 React 代码,能改组件、能跟教程做出界面「能写 CRUD,能排查简单线上问题」L0 + L1 完成即达
职业线
(本课目标)		独立交付完整功能;做选型决策;review AI 的前端产出并识破坑「能做技术选型,能 code review」L0–L3 + L4 项目上线
专家线渲染原理、构建链、极限性能优化「手写 JVM、调 GC 参数」不设课(除非工作刚需)

为什么职业线必须自己走一遍、不能全外包给 AI?看三个 AI 最常犯的前端错误——AI 自己修不好这些,因为它看不出「意图」和「代价」:

⚠️ AI 生成前端代码的三大经典坑(L1/L3 逐个拆解)
  • useEffect 依赖死循环:effect 里改了依赖的状态 → 触发 effect → 再改……界面直接卡死。AI 写出它很容易,自己发现很难。
  • 状态放错层级:状态放在太高的组件,输入框打一个字、整棵树重渲染,页面越用越卡。语法完全正确,性能完全错误。
  • 服务端/客户端边界混乱(Next.js/RSC 时代的新坑):server 组件里用了浏览器 API,或把密钥打包进了客户端代码。编译能过,上线出事。

这三个坑的共同点:代码「对」,行为错。识破它们靠的不是语法知识,是渲染模型和架构判断——这正是「职业线」的全部含义,也是社区共识「AI 时代基础更不能跳」的原因(见 freeCodeCamp 的讨论)。所以我们的契约是:

知识获取,你尽可以用 AI 加速;但每个心智模型都必须亲手跑代码验证。(沿用你在调度课立的规矩:代码你来跑,我负责提醒。)

小结

  • 前端 = 跑在用户设备上的客户端系统,浏览器是它的操作系统;你的领地从「响应到达用户设备」开始。
  • 前端的核心问题只有一个:状态在哪里、怎么变、界面怎么跟着变。React 的回答是 UI = f(state)。
  • React ≈ 界面的 K8s / 数据库视图:声明期望,同步自动完成;「重渲染」是性能与 bug 的发源地。
  • AI 时代的目标线是职业线:能架构、能 review AI 产出。三大经典 AI 坑都靠心智模型识破,不靠语法。
  • 契约:知识可以 AI 加速,心智模型必须亲手验证。
