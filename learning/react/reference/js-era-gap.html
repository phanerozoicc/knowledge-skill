三个深水区(不只是语法)

1. 不可变更新:为什么必须造新数组

React 判断「状态变没变」靠引用比较(Object.is,近似 ===)——相当于「引用就是版本号」。直接 arr.push(x) 或 obj.k = v:内容变了、引用没换,React 视而不见,界面不更新。所以:setItems([...items, x])、setUser({ ...user, name: '新名' })。后端锚:改了缓存内容但没换 key,缓存永远「命中」旧值。

2. 闭包:函数记住它出生时的世界

函数捕获的是定义处作用域的变量绑定,不是当时的值快照。Java/Kotlin 的 lambda 只能捕获 effectively final 变量;JS 闭包更强,也因此有独有的坑:每次 React 渲染都会创建新的闭包实例——「旧闭包里读到旧状态」(stale closure)是 hooks 的头号 bug 来源,L1 见。

3. 事件循环:单线程 ≠ 阻塞

JS 单线程 + 非阻塞 IO,靠事件循环调度——和 Netty/Node 的反应器模型同构。await 不占线程,只是「让出到队列,完成后继续」。所以前端没有「锁竞争」问题,但有「渲染被长任务卡住」问题(16.7ms 一帧的 SLA)。
